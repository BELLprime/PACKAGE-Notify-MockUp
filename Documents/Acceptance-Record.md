## บทที่ 1: วัตถุประสงค์และขอบเขตการตรวจรับมอบงาน (Introduction & Scope)

เอกสารบันทึกการตรวจรับมอบซอฟต์แวร์ (Software Acceptance Record) ฉบับนี้ จัดทำขึ้นภายใต้กระบวนการวิศวกรรมซอฟต์แวร์ **ISO/IEC 29110 (Software Implementation Process: SI.6 Product Delivery และ Project Management: PM.4 Project Closure)** เพื่อเป็นหลักฐานอย่างเป็นทางการในการตรวจรับมอบงานระหว่าง **นางสาวชุณหะกาญจน์ พันธุ์เจริญ (อาจารย์ชุณ)** ในฐานะตัวแทนผู้ว่าจ้าง/ผู้ใช้งานหอพัก และ **ทีม 76 Company** ในฐานะทีมผู้พัฒนา โดยยืนยันว่าผลิตภัณฑ์ซอฟต์แวร์ **"ระบบติดตามและแจ้งเตือนพัสดุหอพัก (RMUTL Smart Dormitory Package Notification & Tracking System)"** ได้รับการพัฒนา ติดตั้ง ทดสอบ และส่งมอบเอกสารประกอบครบถ้วนตามข้อกำหนดในเอกสารข้อกำหนดความต้องการ (`SRS-ENGSE205-2026-V1.0`) และเอกสารการออกแบบ (`DOC-SDD-ENGSE205-03`) ทุกประการ

## บทที่ 2: สรุปผลการทดสอบเพื่อการยอมรับของผู้ใช้งาน (User Acceptance Testing - UAT)

ระบบได้ผ่านการทดสอบการยอมรับของผู้ใช้งาน (UAT) และการทดสอบระบบ (System Testing) ครบถ้วนตามชุดการทดสอบในเอกสาร `Test-Cases.docx` จำนวนทั้งสิ้น **23 กรณีทดสอบ** โดยผลการทดสอบมีอัตราความสำเร็จ **100% (Pass Rate: 100%)** และไม่มีข้อผิดพลาดวิกฤต (Critical Defects) ตกค้าง:

| หมวดหมู่ข้อกำหนด | ขอบเขตการทดสอบ (Scope) | จำนวนเคส | ผลการทดสอบ | อัตราความสำเร็จ |
| :---: | :--- | :---: | :---: | :---: |
| **REQ-FR01** | การบันทึกพัสดุและตรวจสอบชื่อ Exact Match (`TC-FR01`) | 5 เคส | **PASS (5/5)** | 100% |
| **REQ-FR02** | ระบบจำลองการแจ้งเตือนส่วนบุคคลทันที (`TC-FR02`) | 3 เคส | **PASS (3/3)** | 100% |
| **REQ-FR03** | ระบบจำลองการแจ้งเตือนซ้ำพัสดุเกิน 5 ชม. (`TC-FR03`) | 3 เคส | **PASS (3/3)** | 100% |
| **REQ-FR04** | บอร์ดประกาศพัสดุไม่ทราบชื่อและระบบเคลม (`TC-FR04`) | 4 เคส | **PASS (4/4)** | 100% |
| **REQ-FR05** | การลงนามและเซ็นรับพัสดุดิจิทัล Canvas (`TC-FR05`) | 4 เคส | **PASS (4/4)** | 100% |

| **Integration**| Centralized Error Handling และ Route 404 | 2 เคส | **PASS (2/2)** | 100% |
| **รวมทั้งสิ้น** | **การทดสอบระบบครอบคลุมทุกมิติ** | **23 เคส** | **PASS (23/23)** | **100%** |

> ชุดการทดสอบทั้งหมด 23 กรณีทดสอบ ผ่านการทดสอบครบ 100% บนสภาพแวดล้อมเสมือนจริง โดยผู้ทดสอบทั้ง 4 คนได้ลงนามรับรองผลในเอกสาร `Test-Cases.docx` เรียบร้อยแล้ว ระบบมีความเสถียร ไม่พบข้อผิดพลาดระดับร้ายแรง (Severity 1: Blocker) หรือระดับวิกฤต (Severity 2: Critical)

ผลการตรวจสอบความสอดคล้องระหว่างคุณสมบัติของระบบจริง เทียบกับเกณฑ์การยอมรับ (Acceptance Criteria) ที่ระบุไว้ในเอกสาร SRS:

| รหัสเกณฑ์ | หัวข้อความต้องการ | เกณฑ์การยอมรับที่กำหนด (Criteria) | ผลการประเมิน |
| :---: | :--- | :--- | :---: |
| **AC-1.1 - 1.4** | Exact Match & Form | ตรวจชื่อตรง 100%, ทำ Auto-fill ข้อมูลห้อง/LINE, ป้องกันส่งค่าว่าง | **ผ่านเกณฑ์ (Pass)** |
| **AC-2.1 - 2.3** | LINE Notify Mockup | ส่งข้อความได้ภายในเวลา < 3 วินาที, ข้อความครบ 5 องค์ประกอบ, ไม่ส่ง unknown | **ผ่านเกณฑ์ (Pass)** |
| **AC-3.1 - 3.3** | Overdue Reminder | ตรวจจับพัสดุ pending เกิน 5 ชม. ถูกต้อง, แจ้งเตือนซ้ำ, ยกเว้นพัสดุ received | **ผ่านเกณฑ์ (Pass)** |
| **AC-4.1 - 4.3** | Broadcast & Claim | สั่งกระจายขึ้นบอร์ดกลางได้, นศ. กดยื่นเคลมสำเร็จ, อัปเดตผูกนักศึกษา | **ผ่านเกณฑ์ (Pass)** |
| **AC-5.1 - 5.3** | Digital Signature | มีผืนผ้าใบ Canvas ลงลายมือชื่อ, แปลงเป็น Base64 Data URL, บันทึกเวลาจริง | **ผ่านเกณฑ์ (Pass)** |
| **AC-NFR-1 - 2** | Latency & Database | API Response Time เฉลี่ย < 200 ms, ข้อมูลคงทนบน MongoDB หลังรีสตาร์ต | **ผ่านเกณฑ์ (Pass)** |

## บทที่ 4: รายการสิ่งส่งมอบของโครงการ (Summary of Deliverables)

ทีมงาน 76 Company ได้ทำการส่งมอบสิ่งที่สร้างขึ้น (Project Deliverables) ทั้งในรูปแบบซอร์สโค้ดและเอกสารวิศวกรรมซอฟต์แวร์ครบถ้วนตามข้อตกลง ดังนี้:

### 4.1 ซอร์สโค้ดของระบบซอฟต์แวร์ (Source Code Repository)
1. **Backend API Server:** ซอร์สโค้ด Node.js + Express (พอร์ต 5000) พร้อม Mongoose Models, Controllers, และ Centralized Error Handling
2. **Frontend Staff Portal:** เว็บแอปพลิเคชัน React 19 + Vite (พอร์ต 5174) สำหรับเจ้าหน้าที่หอพัก
3. **Frontend Student Portal:** เว็บแอปพลิเคชัน React 19 + Vite (พอร์ต 5173) รองรับการใช้งานผ่านมือถือ (Responsive)
4. **Notification Service:** โมดูลจำลองการส่ง LINE Notify (`mock-line-notify.js`)
5. **Windows Launcher Utilities:** สคริปต์เปิดปิดระบบอัตโนมัติ `start-dev.bat`, `stop-dev.bat`, และ `test.bat`

### 4.2 เอกสารประกอบโครงการตามมาตรฐาน ISO/IEC 29110
1. **Software Requirements Specification (SRS):** เอกสารข้อกำหนดความต้องการ (`Software-Requirements-Specification.docx`) — อนุมัติ 1 ก.ย. 69
2. **Software Design Document (SDD):** เอกสารการออกแบบสถาปัตยกรรมและ BPMN (`Software-Design-Document.docx`) — อนุมัติ 17 ก.ย. 69
3. **API Contract Document:** สัญญาเชื่อมต่อ API ครบทั้ง 16 Endpoints (`API_CONTRACT.docx`)
4. **Test Cases & Results:** เอกสารชุดการทดสอบและผลการรันทดสอบ 23 เคส (`Test-Cases.docx`)
5. **Quick Start & User Guide:** คู่มือการติดตั้งและเปิดใช้งานระบบอย่างย่อ (`README.md`)
6. **Acceptance Record:** เอกสารบันทึกการตรวจรับมอบงานฉบับนี้ (`Acceptance-Record.docx`)

## บทที่ 5: เงื่อนไขการรับประกันและการดูแลรักษาระบบ (Warranty & Support Terms)

* **ระยะเวลารับประกันความบกพร่อง (Warranty Period):** ทีมผู้พัฒนารับประกันแก้ไขข้อบกพร่อง (Bugs / Defects) ของซอฟต์แวร์ที่เกิดจากความผิดพลาดในการเขียนโปรแกรม เป็นเวลา **30 วัน** นับจากวันลงนามตรวจรับมอบงาน
* **ขอบเขตการแก้ไขปัญหา (Scope of Defect Rectification):** ครอบคลุมการแก้ไขกรณีระบบไม่ทำงานตามที่ระบุใน SRS หรือเกิด System Crash โดยไม่คิดค่าใช้จ่ายเพิ่มเติม
* **การสนับสนุนทางเทคนิค (Technical Support Channel):** ตัวแทนผู้ว่าจ้างสามารถติดต่อทีมงาน 76 Company ได้ผ่านช่องทาง LINE Group หรือโทรศัพท์ เพื่อขอคำปรึกษาในการติดตั้งและย้ายฐานข้อมูล

## บทที่ 6: ผลการพิจารณาและการตัดสินใจตรวจรับมอบงาน (Acceptance Decision)

จากการตรวจสอบการทำงานของซอฟต์แวร์ การทดสอบตามชุดกรณีทดสอบ UAT และการตรวจสอบรายการสิ่งส่งมอบครบถ้วน ผู้ตรวจรับมอบงานมีความเห็นและผลการตัดสินใจดังนี้:

* [**X**] **ยอมรับมอบซอฟต์แวร์โดยไม่มีเงื่อนไข (Accepted without Condition)**  
  *ระบบซอฟต์แวร์ทำงานได้ถูกต้องครบถ้วนตามข้อกำหนดทุกประการ พร้อมนำไปใช้งานจริง*
* [  ] **ยอมรับมอบซอฟต์แวร์แบบมีเงื่อนไข (Accepted with Condition)**  
  *ยอมรับงานโดยมีเงื่อนไขให้ทีมพัฒนาปรับปรุงแก้ไขรายการย่อยตามที่ระบุเพิ่มเติม*
* [  ] **ปฏิเสธการรับมอบ (Rejected)**  
  *ระบบไม่ผ่านเกณฑ์การยอมรับขั้นวิกฤต และต้องส่งกลับให้ทีมพัฒนาแก้ไขใหม่ทั้งหมด*

**ข้อคิดเห็นเพิ่มเติมของผู้ตรวจรับมอบงาน (Customer Remarks):**  
> *"ระบบสามารถตอบสนองต่อปัญหาพัสดุตกค้างและหาเจ้าของไม่เจอในหอพักได้อย่างมีประสิทธิภาพ ฟังก์ชัน Exact Match ช่วยลดความผิดพลาดในการกรอกข้อมูล และระบบเซ็นรับดิจิทัลสามารถใช้เป็นหลักฐานยืนยันตัวตนได้อย่างชัดเจน ภาพรวมของระบบมีความสมบูรณ์ตามข้อกำหนดความต้องการที่ได้ตกลงกันไว้"*
