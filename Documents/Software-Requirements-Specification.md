## บทที่ 1: บทนำและสภาพแวดล้อมระบบ (Introduction & Environment Setup)

### 1.1 วัตถุประสงค์ของเอกสาร (Purpose)
เอกสารข้อกำหนดความต้องการของซอฟต์แวร์ (Software Requirements Specification: SRS) ฉบับนี้จัดทำขึ้นเพื่อระบุข้อกำหนดความต้องการทั้งเชิงหน้าที่ (Functional Requirements FR-01 ถึง FR-05) และเชิงคุณภาพ (Non-Functional Requirements NFR-01 ถึง NFR-05) ของ **"ระบบติดตามและแจ้งเตือนพัสดุหอพัก (RMUTL Smart Dormitory Package Notification & Tracking System)"** อย่างเป็นทางการ เพื่อใช้เป็นเกณฑ์มาตรฐานร่วมกันระหว่างทีมพัฒนา (76 Company), ทีมตรวจสอบคุณภาพ (QA & Testers), และผู้ประเมินตามมาตรฐานสากล ISO 29110

### 1.2 ขอบเขตของระบบ (Scope)
ระบบครอบคลุมกระบวนการจัดการพัสดุหอพักแบบครบวงจร 5 มิติหลัก ได้แก่:
1. การบันทึกและตรวจสอบชื่อผู้รับกับฐานข้อมูลนักศึกษาแบบแม่นยำ (Exact Match)
2. การส่งข้อความแจ้งเตือนส่วนบุคคลจำลอง (Mock LINE Notify) ทันทีที่พัสดุถูกบันทึกเข้า
3. การแจ้งเตือนซ้ำอัตโนมัติสำหรับพัสดุที่ค้างรับเกินกว่า 5 ชั่วโมง
4. กระดานประกาศพัสดุไม่ทราบชื่อส่วนกลาง (Broadcast Board) และระบบยื่นสิทธิ์ขอเคลมพัสดุ
5. การลงนามดิจิทัล (Digital Signature Canvas) เพื่อยืนยันการรับพัสดุพร้อมประทับเวลาจริง

### 1.3 นิยาม คำศัพท์ และคำย่อ (Definitions & Acronyms)
* **SRS:** Software Requirements Specification (เอกสารข้อกำหนดความต้องการของซอฟต์แวร์)
* **FR / NFR:** Functional Requirement (ความต้องการเชิงหน้าที่) / Non-Functional Requirement (ความต้องการเชิงคุณภาพ)
* **Exact Match Verification:** การเปรียบเทียบชื่อ-นามสกุลภาษาไทยระหว่างหน้ากล่องกับฐานข้อมูลนักศึกษาแบบตรงกันทุกตัวอักษร
* **Digital Signature:** ลายมือชื่อดิจิทัลที่นักศึกษาวาดลงบนผืนผ้าใบ Canvas และถูกแปลงเป็น Base64 Data URL เพื่อเก็บเป็นหลักฐาน
* **Broadcast Board:** กระดานกลางที่รวบรวมพัสดุไม่ทราบชื่อ เพื่อให้นักศึกษาเข้ามาตรวจสอบภาพถ่ายและยื่นเคลม
* **Mock LINE Notify:** โมดูลจำลองการทำงานของ LINE Notify API โดยแสดงผลผ่าน Server Logger และบันทึกประวัติลง MongoDB

| **วัตถุประสงค์ (Objective)** | ตรวจสอบว่าระบบสามารถบันทึกพัสดุเข้าใหม่ และค้นหา/ยืนยันชื่อนักศึกษาที่มีอยู่จริงในฐานข้อมูล พร้อมทั้งกรอกข้อมูลอัตโนมัติ (Auto-fill) ได้อย่างถูกต้องแม่นยำ 100% |
